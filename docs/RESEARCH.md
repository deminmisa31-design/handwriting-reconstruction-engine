и проверены на Python 3.13/Windows; это не утверждение, что выбраны самые новые версии.

## Дополнительные исследовательские направления

[Handwriting Transformers, авторская публикация ICCV 2021](https://openaccess.thecvf.com/content/ICCV2021/html/Bhunia_Handwriting_Transformers_ICCV_2021_paper.html):
attention связывает локальный/глобальный стиль с контентом; полезен для дальнейшего
few-shot synthesis, но это не гарантия транскрипции или происхождения каждого
штриха. Лицензия реализации/весов не проверена; ничего не скачивалось. Отложить.

[DiffVG, страница авторов SIGGRAPH Asia 2020](https://people.csail.mit.edu/tzumao/diffvg/):
дифференцируемый растеризатор векторной графики; может оптимизировать Bézier
геометрию по растровым метрикам. Prefiltering может давать артефакты, а векторизация
сглаживает индивидуальные детали. Лицензия кода не проверена; отложить P3.

[IAM offline, официальный адрес](https://fki.tic.heia-fr.ch/databases/iam-handwriting-database):
в текущем получении ошибка; условия offline-набора не подтверждены, не загружать.
Прочитанная официальная страница [IAM-OnDB](https://fki.tic.heia-fr.ch/databases/iam-on-line-handwriting-database)
описывает on-line XML/траектории и non-commercial research terms. Эти условия
не переносим автоматически на другой набор; настоящее фото не содержит такой траектории.

[RIMES, первичная публикация Mitek на Zenodo](https://zenodo.org/records/10812725):
французские письма и аннотации документа/слов/строк, релиз 2024, в записи указана
CC BY 4.0 (license link получен из самой записи). Полезен для общей
проверки методов, не русской манеры конкретного автора. Файлы не скачивались;
перед использованием проверить условия именно выбранного релиза. Отложить.

Closed-form matting Levin: попытка чтения PDF с сайта авторов не завершилась
в разумный срок и была остановлена. Метод не реализован и выводов по этому PDF
не делаем. Используется только явно описанная инженерная constant-ink alpha оценка.
Guided filtering, color deconvolution, graph-based matting и dewarp пока остаются
планом сравнительного эксперимента. Нельзя выдавать этот обзор за выполненное
сравнение их качества на настоящих данных.

## Выводы для архитектуры

OpenCV [thresholding](https://docs.opencv.org/4.x/d7/d4d/tutorial_py_thresholding.html):
глобальный Otsu предполагает пригодную гистограмму, adaptive учитывает локальное
освещение. Для бледной синей ручки сначала оцениваем фон и цветовой контраст,
затем выделяем маску. Сетка похожего цвета может остаться; автоматический результат
не становится проверенной буквой.

OpenCV [геометрические преобразования](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html):
warpPerspective для плоского листа, remap для явно заданного поля деформаций.
Гомография не исправляет изгиб книги. Преобразования над масками требуют контроля
интерполяции; координаты разметки должны относиться к конкретной производной.

scikit-image [morphology](https://scikit-image.org/docs/stable/api/skimage.morphology.html):
skeletonize и medial_axis дают разные представления тонкой структуры. Скелет не
восстанавливает порядок штрихов, движение пера и истинные границы букв.
SciPy [EDT](https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.distance_transform_edt.html)
дает расстояние до фона; удвоенное расстояние на скелете — приближенная толщина.
Компонента связности может содержать несколько букв или только точку над буквой.

NumPy [lstsq](https://numpy.org/doc/stable/reference/generated/numpy.linalg.lstsq.html)
подходит для оценки наклона baseline по контрольным точкам; выбросы требуют
устойчивого оценивания. В ядре baseline задается человеком, автоматическая
оценка нижнего квантиля — лишь начальная подсказка.

Pillow [ImageOps](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html)
и [ImageCms](https://pillow.readthedocs.io/en/stable/reference/ImageCms.html):
ориентация EXIF нормализуется в производной, ICC сохраняется в источнике,
поддерживаемый профиль преобразуется в sRGB. Альфа отделяется от бумаги.
Без известного цвета чернил и фона физическое matting недоопределено: здесь
используется оценка alpha по локальному контрасту и выбранному цвету чернил.
Композитинг производится в linear RGB, затем возвращается в sRGB.

Shapely [manual](https://shapely.readthedocs.io/en/stable/manual.html):
геометрические предикаты и операции полезны для сложных полигонов. Для текущего
формата достаточно простых полигонов с проверкой границ и самопересечений;
растеризация выполняется OpenCV, без дополнительной зависимости GEOS.

[CVAT COCO](https://docs.cvat.ai/docs/manual/advanced/formats/format-coco/):
поддерживает bounding boxes и polygons; удобен для будущей массовой разметки.
Встроенный редактор выбран ради полностью локальной установки и собственных
статусов верификации. Экспорт HRE JSON содержит координаты, текст, язык,
baseline и anchors; это не COCO и автоматический импорт чужих label-схем отсутствует.

## HTR, сегментация и русская пропись

Sber AI [пайплайн HTR](https://habr.com/ru/companies/sberbank/articles/716796/)
разделяет детекцию и чтение слов, описывает аннотированные школьные тетради и
необходимость совместной оценки детекции и распознавания. Это источник авторов
самой системы. Распознавание слова не дает надежных границ отдельных букв.
В версии 0.1 используются проекции и горизонтальное замыкание как кандидаты;
транскрипция ручная. На наклонных строках, зачеркиваниях и тесной прописи
нужна коррекция полигонов. Отдельный обученный detector/HTR можно добавить позже,
не меняя статуса candidate и не выдавая confidence за верификацию.

Sber AI [OCR на синтетике GAN](https://habr.com/ru/companies/sberbank/articles/589537/)
рассматривает синтетические обучающие данные для распознавания. Полезность
синтетики для OCR не доказывает сохранение конкретного почерка при генерации.

[handwriting-diffusion README](https://raw.githubusercontent.com/Levos06/handwriting-diffusion/main/README.md):
content-conditioned diffusion для русского почерка, fine-tuning после pretraining.
README сообщает ограниченную точность символов на своих экспериментах.
Это самоотчет проекта, не наши измерения; его веса не скачивались и код не
запускался. Метод не выбран для финального изображения, поскольку текст HRE
должен оставаться точным и прослеживаемым.

## Writer-specific modeling: что измерять далее

Разделить данные по языку и по исходным страницам, а не случайным кропам.
Сначала подтвердить слова/фрагменты, baseline, входы/выходы соединений, масштаб.
Оценить распределения высоты, наклона, ширины, межсловных интервалов,
автокорреляцию параметров соседей и зависимость от позиции в строке.
До этих измерений не добавлять случайный jitter. Текущая версия выводит только
описательные метрики подтвержденных кропов, без имитации обученной манеры.
