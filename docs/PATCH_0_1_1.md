# HRE 0.1.1 — пунктуация, смешанный текст и диагностика сетки

Полученный от пользователя ZIP проверен перед запуском. Его 9 тестов сначала
запущены на исходной версии: 6 failures, 3 passes. После применения патча весь
набор 35+9 прошёл. Добавлена интеграция Store → planner → renderer → validator,
HTTP API и CLI, а также края, не покрытые исходным патчем.

## Композиция

- `--language auto` и «Русский + English» относятся только к композиции;
  язык разметки остаётся ru/en.
- Целый подтверждённый токен сохраняет приоритет. Затем допускаются слово и
  отдельно подтверждённая пунктуация в одной группе переноса.
- Кириллица и латиница определяются по Unicode names, позиции — codepoints.
  Текст, регистр, пробелы, LF и комбинируемые знаки не нормализуются.
- Сохраняются подтверждённые contractions/compounds перед внешней пунктуацией:
  `don't` + `,`. Нейтральные цифры не требуют русских cursive anchors.
- Fixed-language отказывается от чужих букв. Auto не выбирает заведомо неверно
  размеченный язык однописьменного слова. Целый смешанный проверенный токен допустим.
- Strict-real не принимает synthetic даже ради закрытия недостающей пунктуации.

## Сетка: что действительно изменено

Основная `extract_ink` и сохранённые alpha не заменяются. Только по явному флажку
или `analyze --experimental-grid` анализ дополнительно
создаёт `grid_aware_alpha` и `grid_candidates`, явно экспериментальные.
`extract_ink_grid_aware` ищет длинные близкие к осям линии HoughLinesP, требует
повторяющегося шага, оценивает профиль optical density вдоль линий и вычитает его.
Сильное синее свидетельство защищается; без него или без периодической семьи
возвращается базовая маска. Дополнительная диагностика ограничена 4 MP.
Обычный анализ не запускает экспериментальную ветвь; это защищено регрессией.

Контролируемые фикстуры проверяют слабые синие штрихи/точки, пересечения,
низкую цветность штриха, black-ink fallback и одиночный длинный штрих, который
не должен считаться клеточной сеткой. Это не оценка recall на реальных фото.

Первый цветовой вариант был отклонён после визуального просмотра: он удалял
бледные английские штрихи. Профильный вариант сохраняет больше таких деталей,
но остаются линии сетки и локальная неоднозначность. На втором, более плотном
кропе периодическая семья не подтвердилась: метод честно возвращает baseline.
Проблема сетки НЕ объявляется решённой для автоматической библиотеки букв.

## Локальная диагностика без публикации

```text
python -m hre diagnose path/to/crop-a.png path/to/crop-b.png --output private-diagnostics
```

Создаются baseline/experimental/grid PNG, сравнения JPG и JSON с SHA входов.
Доля foreground и уменьшение alpha — описательные числа, не точность/recall.
Для продолжения нужны ручные эталонные маски и полные исходники.

Полученный приватный архив содержал кропы, а не заявленные исходные JPEG.
Хеши оригиналов из приложенного отчёта — сведения отправителя; независимая
проверка невозможна без оригиналов. Кропы хешированы отдельно. Ни изображения,
ни их идентификаторы, содержимое и приватные отчёты не включены в git.

Материалы Hough: [официальная документация OpenCV](https://docs.opencv.org/4.x/d9/db0/tutorial_hough_lines.html).
